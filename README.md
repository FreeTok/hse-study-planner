# Study Planner

Study Planner - это учебное веб-приложение, которое помогает разложить подготовку к дедлайну на понятный план по дням. Я выбрал эту идею, потому что в учебе часто сложно оценить, сколько времени реально осталось до сдачи работы и как распределить нагрузку без аврала в последний вечер.

## Цель проекта

Сделать простой сервис, в котором студент вводит:

- название предмета или задания;
- дату дедлайна;
- примерное количество часов, которое нужно на подготовку;
- сколько часов в день он готов заниматься.

После этого приложение показывает план: сколько дней осталось, сколько часов нужно делать каждый день и есть ли риск не успеть.

## Основная функциональность

Сейчас в приложении есть:

- форму для ввода данных по заданию;
- проверку ошибок, например пустого названия или дедлайна в прошлом;
- расчет учебного плана;
- вывод результата в понятном виде;
- простое API, чтобы frontend не считал все сам.

Возможные примеры результата:

- "До дедлайна осталось 5 дней, нужно заниматься по 2 часа в день";
- "План выглядит нормально, есть небольшой запас";
- "Есть риск не успеть, потому что доступного времени меньше, чем нужно".

## Стек

- Frontend: HTML, CSS, JavaScript.
- Backend: Node.js.
- Тесты: встроенный тестовый модуль Node.js.
- CI: GitHub Actions.
- Контейнеризация: Docker.
- Статический анализ и безопасность: Semgrep, Trivy или Syft.

Я специально беру простой стек без большого фреймворка, чтобы лучше разобраться в базовой структуре веб-приложения: запросы, ответы сервера, обработка ошибок и запуск проекта.

## Архитектура

Сейчас структура проекта такая:

```text
study-planner/
  public/          # frontend: страница, стили и клиентский JavaScript
  src/             # backend и бизнес-логика
  test/            # тесты
  docs/            # отчеты и заметки по проекту
  Dockerfile       # запуск приложения в контейнере
```

Логика расчета вынесена отдельно от HTTP-сервера. Так ее проще тестировать: тесты смогут проверять расчет плана без запуска браузера.

## Запуск проекта

Нужен Node.js версии 20 или новее.

```bash
npm start
```

После запуска приложение открывается по адресу:

```text
http://localhost:3000
```

Проверка синтаксиса:

```bash
npm run check
```

Запуск тестов:

```bash
npm test
```

## CI

В проекте есть GitHub Actions workflow `.github/workflows/ci.yml`. Он запускается на Pull Request и на push в `main`.

Сейчас pipeline делает две вещи:

- устанавливает зависимости через `npm ci`;
- запускает `npm run check`, чтобы проверить синтаксис backend и frontend JavaScript;
- запускает `npm test`, чтобы проверить расчет плана и API.

## Docker

Сборка образа:

```bash
docker build -t study-planner .
```

Запуск контейнера:

```bash
docker run --rm -p 3000:3000 study-planner
```

После запуска приложение доступно по адресу:

```text
http://localhost:3000
```

## Как я буду оценивать успех

Проект можно считать полезным, если пользователь может открыть приложение, ввести данные по учебному заданию и сразу получить понятный план подготовки. Для меня важно не просто сделать красивую страницу, а довести проект до состояния, где его можно запустить, проверить и передать другому человеку.
