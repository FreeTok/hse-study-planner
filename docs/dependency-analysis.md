# Анализ зависимостей

В проекте почти нет внешних зависимостей: приложение написано на стандартных модулях Node.js и обычном браузерном JavaScript.

## SBOM

SBOM я сгенерировал в формате CycloneDX командой:

```bash
npm sbom --sbom-format cyclonedx > reports/sbom.cdx.json
```

Файл отчета: `reports/sbom.cdx.json`.

Главный вывод: в поле `components` сейчас пустой список, потому что проект не использует сторонние npm-пакеты.

## Проверка уязвимостей

Проверку зависимостей я выполнил командой:

```bash
npm audit --omit=dev
```

Результат:

```text
found 0 vulnerabilities
```

JSON-отчет сохранен в `reports/npm-audit.json`.

## Что делать при появлении уязвимостей

Если позже я добавлю зависимости и `npm audit` найдет проблемы, план такой:

1. Проверить, относится ли уязвимость к production-зависимостям.
2. Обновить пакет до безопасной версии через `npm update` или точечное изменение версии.
3. Если обновление ломает код, найти безопасную альтернативу или убрать зависимость.
4. Повторить `npm test`, `npm audit --omit=dev` и сборку Docker-образа.

## CI

В GitHub Actions добавлен job `dependency-analysis`. Он генерирует SBOM, запускает аудит зависимостей и сохраняет отчеты как artifact `dependency-reports`.
